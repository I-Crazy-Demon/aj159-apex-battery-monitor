# AJ159 APEX Battery Monitor

Фоновый монитор заряда батареи мыши **Ajazz AJ159 APEX** для Windows 10/11:
иконка-батарейка в системном трее, уведомления о низком заряде и
автоматическая синхронизация часов на экранчике докстанции.

Официального SDK или документации на протокол этой мыши не существует.
Весь протокол в этом проекте получен реверс-инжинирингом — перехватом
реального HID-трафика между официальным веб-конфигуратором
[qmk.top](https://qmk.top/v4/index.html) и устройством, через браузерный
[WebHID API](https://developer.mozilla.org/en-US/docs/Web/API/WebHID_API).
Подробности — в разделе [Как был получен протокол](#как-был-получен-протокол).

![Иконка в трее](battery_icon_preview_horizontal.png)

## Возможности

- Точный процент заряда (не 4-сегментная шкала, как в официальном
  веб-конфигураторе) в виде иконки-батарейки в трее.
- Цветовая индикация: зелёный (100–50%), жёлтый (49–15%), красный (14–5%),
  мигающий красный (<5%).
- Toast-уведомление при достижении порога низкого заряда.
- Автоматическая синхронизация времени на экранчике докстанции (сбрасывается
  при полном отключении питания докстанции) — сразу при запуске и затем
  периодически.
- Работает как обычный Python-скрипт или как отдельный `.exe`
  без зависимости от установленного Python.

## Требования

- Windows 10/11
- Python 3.9+ (если запускать как скрипт; для `.exe`-сборки не требуется
  на машине конечного пользователя)
- Мышь AJ159 APEX, подключённая через фирменную докстанцию/донгл

## Установка (запуск как Python-скрипт)

```
pip install -r requirements.txt
```

или вручную:

```
pip install hidapi pystray pillow plyer
```

## Использование

```
ajazz_battery.py check
```
Разовая проверка: печатает сырой ответ устройства и разобранный процент заряда.

```
ajazz_battery.py sync-time
```
Разовая синхронизация часов докстанции с системным временем ПК.

```
ajazz_battery.py monitor [опции]
```
Запускает фоновый монитор с иконкой в трее.

| Флаг | По умолчанию | Описание |
|---|---|---|
| `--interval N` | 120 | Опрос заряда раз в N секунд |
| `--threshold N` | 20 | Порог уведомления о низком заряде, % |
| `--sync-interval N` | 3600 | Синхронизация времени докстанции раз в N секунд |

Пример:
```
ajazz_battery.py monitor --interval 300 --threshold 15 --sync-interval 1800
```

Справка доступна пятью привычными способами — все дают одинаковый вывод:
```
ajazz_battery.py help
ajazz_battery.py --help
ajazz_battery.py -h
ajazz_battery.py /?
ajazz_battery.py ?
```

Любой другой нераспознанный ввод (опечатка в команде, неизвестный флаг)
не показывает список допустимых значений — только короткую строку
`usage: ...`, без подробностей.

Если устройство не отвечает — закройте вкладку с qmk.top в браузере
(WebHID может удерживать HID-интерфейс монопольно) и повторите попытку.

## Сборка автономного .exe

Чтобы не зависеть от установленного на машине Python (в том числе от
версии, установленной из Microsoft Store — её внутренний путь меняется при
каждом обновлении и ломает жёстко прописанные пути):

```
pip install pyinstaller
pyinstaller --onefile --noconsole --name AJ159BatteryMonitor ^
    --icon=app_icon.ico ^
    --hidden-import=plyer.platforms.win.notification ^
    ajazz_battery.py
```

(`^` — перенос строки в `cmd.exe`; в PowerShell используйте `` ` ``, либо
пишите одной строкой.)

Флаги:
- `--onefile` — весь Python-рантайм и зависимости упаковываются в один файл.
- `--noconsole` — без окна консоли при запуске `monitor` (аналог `pythonw.exe`).
- `--icon=app_icon.ico` — иконка самого exe-файла в проводнике.
- `--hidden-import=...` — plyer подгружает платформенный бэкенд уведомлений
  динамически, PyInstaller иногда не видит его сам; без этого флага toast
  может молча не показываться.

Несмотря на `--noconsole`, команды `check`/`sync-time`/`help` в собранном
`.exe` всё равно печатают вывод: при запуске не как `monitor` программа
сама прицепляется к консоли процесса-родителя (если вызвана из уже
открытого cmd/PowerShell) либо создаёt новое консольное окно (если
запущена двойным кликом) и делает паузу `Нажмите Enter для выхода...`
перед закрытием, чтобы вывод не исчез мгновенно. Один и тот же `.exe`
одинаково годится и для `monitor` (без единого мелькания окна), и для
разовых команд.

Результат: `dist\AJ159BatteryMonitor.exe` — один файл, Python на целевой
машине не нужен. Первый запуск может насторожить Windows
Defender/SmartScreen (неподписанный exe) — это ожидаемо для самодельных
сборок, просто разрешите запуск.

Использование `.exe` идентично скрипту:
```
AJ159BatteryMonitor.exe monitor
AJ159BatteryMonitor.exe check
AJ159BatteryMonitor.exe --help
```

## Автозапуск

### Вариант А — папка автозагрузки (просто)

1. Узнайте путь к `pythonw.exe` (если используете Python-версию) или
   к собранному `AJ159BatteryMonitor.exe`.
2. `Win+R` → `shell:startup` → создайте ярлык:
   - Для Python-версии — объект:
     `"C:\путь\к\pythonw.exe" "C:\путь\к\ajazz_battery.py" monitor`
   - Для `.exe`-версии — объект:
     `"C:\путь\к\AJ159BatteryMonitor.exe" monitor`

**Если Python установлен из Microsoft Store** — не указывайте путь внутрь
`Program Files\WindowsApps\...` напрямую: это версионная папка, она меняет
имя при каждом обновлении Store-пакета и ярлык сломается. Используйте
стабильный alias-путь, который Windows поддерживает специально для этого:
```
%LOCALAPPDATA%\Microsoft\WindowsApps\pythonw.exe
```
Либо соберите `.exe` (см. выше) — тогда зависимости от Python вообще нет.

### Вариант Б — Планировщик заданий (надёжнее, есть журнал)

```
schtasks /create /tn "AJ159 Battery Monitor" ^
    /tr "\"C:\путь\к\AJ159BatteryMonitor.exe\" monitor" ^
    /sc onlogon /rl limited
```

Проверить: `schtasks /query /tn "AJ159 Battery Monitor"`
Удалить: `schtasks /delete /tn "AJ159 Battery Monitor" /f`

## Как был получен протокол

1. Официальный конфигуратор [qmk.top](https://qmk.top/v4/index.html)
   общается с устройством через браузерный WebHID API.
2. В консоли разработчика браузера (F12) переопределялись методы
   `HIDDevice.prototype.sendFeatureReport` / `receiveFeatureReport`, чтобы
   логировать все отправляемые и получаемые байты при выполнении разных
   действий на сайте (просмотр заряда, синхронизация времени и т.д.).
3. Полученные hex-дампы анализировались вручную — сопоставлением известных
   величин (текущее время, видимый процент заряда) с байтами в пакетах.

Из-за такого способа получения протокола часть полей (например, байт[3] в
ответе статуса) остаётся нерасшифрованной — они не влияют на работу
монитора, но и не используются.

## Известные ограничения

- Экран докстанции в простое (>20 сек без движения мыши) принудительно
  показывает статус радиосвязи поверх любого контента — это поведение
  прошивки, обойти его программно не удалось (проверено: заливка
  собственной картинки и очистка экрана одинаково перекрываются статусом
  связи через 20 секунд).
- Протокол подтверждён только на реальном экземпляре AJ159 APEX автора;
  для других моделей линейки Ajazz (и даже других экземпляров той же
  модели с другой прошивкой) поведение не гарантируется.
- Байт[3] в ответе команды статуса не расшифрован.
